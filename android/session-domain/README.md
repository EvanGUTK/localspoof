# Phone-owned session domain

Plain Kotlin/JVM, no Android, files, sockets, persistence, or operational logging. Android parses static GeoPack resources and injects samples returned by `Coordinator.tick(elapsedRealtimeMillis)` through its provider adapter. A clock supplier controls wall timestamps in tests.

`prepare` builds outside the coordinator lock against frozen resources and a revision/cancellation generation. `commit` atomically replaces complete plans only on the matching revision. Phone Stop invalidates preparations. Start requires app-layer visible-phone/service checks. Dismissing UI does not affect this memory owner; process death cannot reconstruct it.

For resource imports, call `prepareResources(pack, airports)` outside app/session locks and install its opaque handle with `installResources`. That keeps graph validation and copies out of the phone Stop critical section. Existing playback uses its complete geometry until replaced. Capture `recoveryAirplaneState` before Stop only to display static manual recovery guidance; Stop discards that memory.

Walking/driving use profile-restricted Dijkstra for offline GeoPacks. Origins/destinations must lie inside pack coverage and within 250 meters of a routable graph node. Alternatively, a paired desktop can supply `OnlineRoute` geometry with an explicit WALK or DRIVE profile. Online input is untrusted: finite coordinates, profile, point counts, segment/total length, provider-label bounds and endpoint snapping are validated; supplied lists are copied before preparation. At most 12,000 points are accepted, including both airport ground legs combined. Individual segments are limited to 100 km and each route to 20,000 km. Phone-selected speeds and timing remain authoritative; network estimates and claimed speed limits do not control playback.

Preview returns actual snapped endpoints and `routeSource` (`ONLINE_ROUTER`, `OFFLINE_GEOPACK`, `CUSTOM_PATH` or `INSTANT_LOCATION`). Road access, provider identity and routing quality are not independently certified by the phone. No missing-road fallback or hidden connector to requested endpoints exists. Explicit custom paths require matching first/last endpoints and are labeled by `preview.customPath`. Resource parser is an Android concern; static graph/list objects are copied at the coordinator boundary.

Routes accelerate, respect edge speed caps, decelerate near endpoints, support waypoint dwell, and finish Holding. Pause and scheduling gaps exceeding five seconds hold the last point while fresh samples continue. Samples have increasing monotonic timestamps. Coordinate interpolation crosses the antimeridian correctly. `suggestFlight` uses a strict greater-than 402,336-meter threshold.

Flight phases run on the phone. An online flight supplies both complete DRIVE ground legs and exact catalog airport IDs through `OnlineFlightRoutes`; selected IDs must agree and the airports must remain eligible. User-requested endpoints retain the 250-meter snap tolerance; online departure/arrival airport access points may lie within 5,000 meters of their identified catalog airport centroids. Preview discloses both access distances. The online air leg uses actual road-access endpoints for its distance and timing estimate; it does not connect or jump to catalog centroids. Offline flights continue to prepare both legs from the graph. Airport catalog coordinates identify the selected airport; `originAirportAccessPoint`/`destinationAirportAccessPoint` identify the validated ground geometry endpoints actually held/placed. Do not create a hidden connector jump between catalog centroids and snapped roads. Read actual airplane mode through `observeRadio` before Start. Guided transitions wait for observed state; simulation-only phases skip radio claims. `snapshot.desiredAirplaneMode` identifies a requested setting only at the waiting/restoration phase. Do not acknowledge a shell command merely because it was sent. Destination placement waits for successful provider submission via `acknowledgePlacement(true)` and a settling interval. A failed submission enters Error. A radio change during the flight interval pauses and requires renewed observation before Resume. Replacement is blocked while a changed radio state still needs restoration. Radio/placement acknowledgment waits do not consume simulated travel elapsed time.

Always call platform cleanup before discarding runtime ownership. Before Stop, app/native layers must preserve only the live recovery instruction needed for the setting they changed; no persistent recovery journal exists. Process death can leave radios/mock overrides needing manual recovery.

Run from the Android build root with an equipped JDK/Gradle environment:

```sh
gradle :session-domain:test :session-domain:jacocoTestReport
```

The previous Windows Gradle build passed all 35 domain tests on 2026-10-02. Eight online geometry/flight tests cover independent playback without an offline pack, provenance, snapping, mutable-list isolation, point/length/profile limits, airport selection and placement phases. The airport-access update adds two further tests; the new build result is recorded in `docs/ANDROID_BUILD.md`. JVM tests do not qualify Android providers or physical devices; Node/Rust tests elsewhere do not prove this Kotlin engine or device behavior.

Minor 4 adds `setSpeeds` and `jumpToNextStop`. Speeds are independent WALK0.1–3, DRIVE0.1–55, FLIGHT30–350 m/s targets; edits preserve progress and elapsed time and apply during pause on resume. Legacy flight durations are accepted only when their implied speed falls in the flight bounds; explicit `flightSpeedMps` takes precedence. Estimated remaining time is recomputed from current remaining edge distances/caps, unconsumed dwell and air distance. Acceleration and user-controlled radio wait make it an estimate. Paused/provider/radio waits return null ETA and an explicit `waitingFor`; elapsed time is not repurposed as arrival time.

Up to32 ordered `RouteStop` values carry names and dwell. Custom paths resolve exact interior stop vertices; online routes require one strictly increasing `stopPointIndices` index per stop within250m; offline planning joins complete graph legs without hidden connector lines. Jump only accepts an active travel phase and current revision. The current provider must successfully submit the target before advancing/dwelling; boarding, pause, dwell, settling and radio ownership cannot be bypassed. Airport eligibility now requires open scheduled-service `large_airport` metadata for automatic and manual selection. RegionalJackson airport is explicitly rejected by regression.
