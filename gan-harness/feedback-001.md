## Definite findings communicated to the builder

1. **MEDIUM — invalid default ADB executable, corrected.** `desktop/ui/index.html` previously initialized the path as `adb`; `Adb::new` requires an absolute existing executable. The default Scan therefore always failed. With explicit builder authorization, the evaluator changed UI default/reset to blank, added an absolute-path helper and preflight validation, and retained the backend restriction. Regression evidence: the new model path test failed at its implementation stub and the DOM test failed on the old default; both pass after correction. Empty/relative/wrong-name paths fail before native invocation. The full UI test files and asset build pass after the change.

2. **MEDIUM — Android selection leaves a stale prepared plan, corrected at source.** `MainActivity.kt` callbacks for “Use current simulated position” and imported place search change coordinate fields without invalidating `preparedId`. Manual coordinate and airport inputs do invalidate it. The selection callbacks can therefore leave “Start this plan” targeting the previous prepared destination/origin. Reported immediately to the root builder. Follow-up source inspection confirms both callbacks now set `preparedId = null`. Android runtime regression remains part of the unexecuted integration gate.

3. **MEDIUM — APK hash verification is not bound to installed bytes, corrected at source.** `desktop/native/src/adb.rs::Adb::install` hashes an opened file, then passes its original pathname to `adb install`. A file modification/replacement between verification and ADB's read can change the bytes being installed. Reported immediately. Independent follow-up source inspection confirms `read_verified_apk` checks a regular file and a 200 MiB bound, hashes the returned byte vector, and passes that same vector into stdin. The command contains only fixed `shell -T cmd package install -r -S <length> -` tokens and the validated selected USB serial, never the source pathname. It requires an exact `Success` output line; stdin/stdout/stderr and process status share a deadline with 64 KiB output limits. The builder reports five targeted regressions plus 13 total passing native Rust tests and passing Clippy; that is synthetic process evidence, not PackageManager hardware qualification.


4. **MEDIUM — stale service tick can mutate a successor, corrected at source.** Notification publication and first-stop guards fix duplicate teardown and old notification races. The evaluator additionally identified a delayed ordinary settings read that could resume into the shared runtime after an old coroutine was canceled. Independent follow-up inspection confirms `RuntimeModel.tick` and `failOwner` now check the captured provider identity and `serviceRunning` under the runtime mutation lock before lease, radio, provider or snapshot effects. The service captures its provider owner, rejects commands after its stopped flag, and makes repeated stop/destruction idempotent. Kotlin compilation and Android lifecycle stress tests remain unexecuted.

5. **MEDIUM — generic dwell control misstates the wire behavior, corrected.** The desktop originally exposed a dwell input for all modes with an 86400-second limit, while `dwellSeconds` represents flight boarding and is bounded to 3600 by the wire. With explicit builder authorization, the evaluator changed the label to “Boarding hold”, displays it only for Flight, enforces 0–3600 seconds, and ignores hidden flight fields during nonflight preparation. The targeted model test failed when 3601 was accepted, then passed after correction. DOM checks assert visibility follows the selected mode. The UI README states waypoint dwells belong to the domain API and are not an editor/automatic route-pause feature of this UI.

6. **MEDIUM — ended desktop lease retains setup values and accepts stale polling effects, corrected.** `loseConnection` now clears selected device/model options and ADB/APK input paths as well as session activity. An in-flight Snapshot could previously finish after Stop and redraw Active state over the manual radio restoration message. The new deferred-poll regression reproduced that exact outcome before correction. Polling now checks the captured activity epoch, socket state and stop flag after every awaited stage and before error recovery; requests reject stale epochs before changing revisions; old poll/run finalizers cannot clear a successor's busy state. Stop preserves its restoration guidance and remains disconnected after the late Snapshot arrives. The builder additionally reproduced a rejected Stop leaving `busy` set after the canceled poll finalizer was excluded; the Stop finalizer now explicitly clears `busy` before clearing `stopping`, while a successor operation is still prohibited. Independent inspection confirms the parameterized deferred-poll test covers both confirmed and rejected Stop, including an enabled Disconnect control and unchanged rejection status after the late reply. All four synthetic DOM tests pass; actual USB/socket races still belong to physical qualification.

7. **Radio Stop qualification caveat addressed in source.** Android `RuntimeModel.stop` now captures whether a USB flight is active/paused/holding/errored before revocation. It preserves an explicit instruction to check airplane mode manually because an already-running USB radio operation can finish after phone Stop. Cleanup failure additionally directs the user to reset providers. Independent inspection confirms the guidance is captured before the active policy/session are erased and repeated Stop retains the static manual guide. Source cannot guarantee cancellation of an already-issued external ADB radio command; this remains a physical timing/recovery qualification case.
