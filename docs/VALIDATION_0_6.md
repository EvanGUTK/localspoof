The first renderer correction fixed discarded tile bursts and premature state application: four active requests, at most 32 bounded waiters, separate 12-second admission/response budgets, and deferred state replay. That isolated harness loaded tiles successfully, but the user still saw a blank map in the subsequent release. Same-package diagnostics identified a second cause: a zero-height document/map surface despite nonzero Android viewport height and hundreds of rendered features.

The final correction gives the WebView factory ownership, starts only after attachment with nonzero dimensions, coalesces resize updates, supplies viewport-height CSS, and applies a bounded `innerWidth`/`innerHeight` pixel fallback. Actual S24 candidate observation verifies map/gear/Settings/return navigation, keyboard shrink/restoration, and Home/reopen with the map ready. Diagnostic capture temporarily changed screen-security/debug flags; the final signed production build restores those protections and is installed with matching bytes. Fixed-provider paths, body/time limits, CSP, blocked default WebView networking, and disabled storage remain in place. See [mobile render review](V06_MOBILE_RENDER_REVIEW.md).

This is bounded recovery evidence, not proof of cause or sustained USB stability. Ordinary app scans do not kill a shared daemon.
