# ECC security review

Reviewed 2026-10-02 using ECC `security-review` as requested by the build pipeline, with final Windows artifact evidence inspected on 2026-10-03 UTC. This covers source boundaries, build/test results, signing and packaging. It is not a device penetration test, dependency vulnerability audit, or proof that webview/OS/SDK activity never reaches disk. A narrowly scoped real S24 companion installation and public handshake were subsequently exercised; see the current validation record.

## Findings and remediation

| ID | Severity | Finding | Status |
|---|---|---|---|
| S1 | HIGH | Unauthenticated socket replies returned current coordinate, session state, revision and session identifier | Fixed in reviewed source: static `publicResponse` for capabilities/pairing/parsing/auth failures, credential delivery includes approved session ID only |
| S2 | HIGH | Large GeoPack parsing/validation held the same runtime lock required by phone Stop and playback | Fixed in reviewed source: parsing and opaque-resource preparation run outside the lock, then authorization/revision are checked again before a lightweight install; device timing qualification remains required |
| S3 | MEDIUM | Authenticated desktop Stop could be rejected after a natural state transition because its expected revision was stale | Fixed in source: Stop exempt from revision equality; credentials/session/sequence still required |
| S4 | MEDIUM | A preauthentication client could monopolize the single socket worker by sending bytes just before each read timeout | Fixed in source: absolute five-second header/body frame deadline, two-minute preauth deadline, explicit reenable closes old socket and guards stale disconnect generation |
| S5 | MEDIUM | Desktop device serial filtering did not prove USB transport and could accept mDNS wireless ADB identifiers | Fixed in reviewed source: reject TLS/mDNS identifiers, verify USB devpath at selection/install, pin loopback server host/port, sanitize inherited routing/trace/serial settings and disable mDNS autoconnect |
| S6 | MEDIUM | Stop during a journey cleared radio ownership without visible guidance when the app's requested airplane-mode change remained active | Fixed in reviewed Android/frontend source: capture recovery requirement before Stop and retain/display only generic manual-settings guidance |
| S7 | MEDIUM | Desktop disconnect cleared the live snapshot but kept entered coordinates, selected airports, route geometry and camera position | Fixed in reviewed frontend source: call activity discard on disconnect, including after phone-local Stop revokes the lease |
| S8 | MEDIUM | Specialized plan/resource dispatch bypassed command-ID length checks and cached preview objects before enforcing response byte limits | Fixed in reviewed source: uniform envelope limits, frame-bounded response entries, maximum 32 acknowledgments and 2 MiB aggregate serialized responses |
| S9 | MEDIUM | Offline converter's raw ASCII DTD/entity checks could be bypassed by UTF-16 XML | Fixed: strict UTF-8 decoding and decoded-text DTD/entity policy; independent synthetic reproduction now rejects the same encoded input |
| S10 | MEDIUM | Desktop APK install hashed an open file then let ADB reopen its pathname, allowing source replacement after verification | Fixed: verify one bounded in-memory buffer, pass that exact owned buffer to raw-stdin package installation, require an exact Success line; synthetic process tests pass |

S1 original sink was `android/app/src/main/kotlin/dev/localspoof/android/RuntimeModel.kt:166` (`response` always serialized current state), reached from public and error paths in `PhoneControlServer.kt`. Current public helper contains no runtime snapshot fields. Invalid commands cannot obtain coordinates. Only a credential approved on phone obtains the live authenticated response. This fix deserves a regression test against actual dispatch, in addition to helper-shape tests.

S2 original sink was `PhoneControlServer.dispatchLocked`, where `ImportGeoPack` and `CommitGeoPack` parsed up to 16 MiB under `RuntimeModel.lock`. The resource dispatcher now parses outside the lock and rechecks authorization/revision before installation. `Coordinator.prepareResources` returns an opaque validated/frozen handle; `installResources` is the short mutation. App callers must not wrap preparation/freezing in the runtime lock. Hashing and buffer copying are bounded but should also stay outside long critical sections where possible. Stopping revokes the lease and invalidates preparations, so a delayed parse cannot activate activity.

S3 is addressed at the mutation revision check in `PhoneControlServer.kt`; the native bridge already exempted Stop from its stale-revision rejection. Stop remains credential-protected and sequence-checked, so this does not permit an unpaired process to stop a session.

S4 is addressed in `PhoneControlServer.handle` and explicit service reenable. Verify the deadline using partial header/body senders. A fixed-capacity worker plus bounded frames does not by itself enforce a total time bound.

S5 sinks were `desktop/native/src/adb.rs:21` (serial characters), `adb.rs:28` (`parse_devices`), and `desktop/native/src/bridge.rs:95` (`connect`). A serial matching allowed characters is not evidence of USB. Known TLS/mDNS names must be excluded and selected transport positively checked without relying solely on `usb:` in `devices -l`: [AOSP ADB documentation](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md) says that prefix can be absent with the libusb backend. Exact `-s` targeting remains necessary. Pin ADB server host/port to loopback and disable inherited server-routing/autoconnect settings rather than removing only `ADB_TRACE`.

S6 sinks were `RuntimeModel.stop` and the `Stop` arm in `desktop/native/src/bridge.rs:70`. Clearing ownership is correct for memory-only privacy, but recovery guidance must survive as a static message without coordinates, airports, routes or credentials. `Coordinator.recoveryAirplaneState` now exposes only the setting owed while state remains live. No automatic restoration should occur after user intervention or lost ownership. Process death still requires manual recovery because no journal is permitted.

S7 sink is `desktop/ui/src/app.ts:80`, `loseConnection`. Reset snapshot fields alone does not discard the route and form state. Use the same activity discard routine as explicit desktop Stop, then replace status with disconnected/manual recovery guidance. Static imported geographic resources may remain loaded. Android already clears form coordinates, query and airport selection when the coordinator enters Idle after Stop.

S8 sinks are `PhoneControlServer.dispatch` (specialized `PreparePlan`) and `dispatchResource`, which initially skipped the generic `commandId.length in 1..128` check. The prepared preview was cached before the output framing code rejected a response exceeding 1 MiB. Count limits alone allowed oversized keys and previews to accumulate. Validate every envelope consistently and ensure an acknowledgment entering the cache fits the frame byte limit, or cache only a bounded summary and use explicit bounded geometry transfer. This is an authenticated robustness issue, not an unpaired mutation bypass.

S9 sink is `tools/build-geopack.py`, `convert`, which initially checked `raw.upper()` for ASCII DTD/entity tokens then passed the raw byte stream to ElementTree. A synthetic UTF-16 document with an internal entity was accepted and converted, bypassing the declared entity prohibition. This is not evidence of external-file XXE; ordinary ElementTree does not normally resolve external entities. Enforce a supported encoding policy before DTD/entity checks, then parse only the checked decoded text. Add encoded-document regression coverage. The converter processes static developer-provided data and is separate from the shipping runtime.

S10 sink was `desktop/native/src/adb.rs`, `Adb.install`: its file digest check did not bind the later APK-path read to the verified bytes. The bounded repaired reader opens a regular absolute `.apk`, hashes the same <=200 MiB buffer transferred to installation, and never reopens or stages it at runtime. Windows physical testing later found binary corruption through generic shell stdin, so current installation uses private `desktop/native/src/install.rs`: fixed loopback ADB smart socket, exact validated selected-device transport, fixed `exec:cmd package install --user 0 -r -S <verified length>`, raw verified bytes, bounded statuses and absolute deadline. It requires definitive Success and offers no generic command IPC, downgrade, uninstall or permission grant. This production path returned Success on the attached S24 with the signed baseline APK. [Official AOSP streamed installer](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/adb_install.cpp) is the protocol reference.

Five new Rust tests use synthetic files/processes: replace the source APK during the USB probe and verify original bytes reach stdin with exact serial/size; reject wrong hashes, empty and oversized bytes; reject successful process exit without an exact Success line; enforce the shared stdin/output/process deadline; and fail closed on oversized stdout. No test claims an actual Android install. The shared tool executor polls writer/readers and child completion within the deadline, rather than blocking indefinitely on reader-thread joins after child exit. Standard output/error remain transient and bounded, and no diagnostic payload is exposed.

## Controls checked in source

- Android service is private, visible, user-started and not sticky; manifest omits internet access and includes backup/extraction exclusions.
- Framework provider preserves mock markers, checks app-op/location readiness, rolls back partially prepared providers, and cleans only tracked provider names. Actual hard-stop restoration remains device-dependent and untested.
- Frames are length-prefixed, reject invalid/oversized lengths before body allocation, and parse strictly bounded JSON. Resource imports bound bytes, graph sizes, indices/chunks, hash and transfer lifetime. JSON depth and malformed UTF-8 checks are present in the Android parsing adapter.
- Pairing uses ephemeral random material, phone approval, a single live lease, constant-time credential comparison, failed-attempt bound and heartbeat expiry. Mutation authorization precedes snapshots or operations. Replayed command IDs are accepted only for matching bounded cached fingerprints.
- Desktop UI receives neither controller token nor generic shell access. Native phone commands are allowlisted. ADB uses argument arrays, exact device selection, read/write timeouts and capped transient output. APK installation requires a build-supplied trusted hash; the packaged desktop build passed the signer/package/release checks described below.
- Radio requests are phase-specific; native rereads the phone request and observed setting. App re-observes the platform setting instead of trusting desktop claims. Ownership-aware restoration rejects user-overridden state.
- Phone Stop cannot atomically cancel an already issued external ADB radio operation. USB-flight Stop preserves static manual radio-setting guidance even if the change has not yet been observed; actual Stop/ADB ordering must be qualified on hardware.
- Tauri uses local-only capabilities, restrictive CSP, incognito and disabled devtools. Actual webview file/cache/crash audit remains unperformed.
- Reviewed production source contains no intentional operational logging, telemetry, browser storage, user activity database or diagnostic exporter. Absence of source sinks is not runtime filesystem evidence.

## Build and signing script review

`tools/build-android.ps1` now checks the Gradle 8.13 wrapper JAR against its official SHA-256, requires the official binary distribution URL, and enforces its official distribution SHA-256 before executing the wrapper. These are separate integrity controls described by [Gradle's wrapper verification documentation](https://docs.gradle.org/current/userguide/gradle_wrapper.html). Release configuration explicitly disables debugging. Build failures and tool exit codes fail closed; physical-device qualification is separate.

`tools/build-desktop.ps1` requires an independently supplied trusted release certificate fingerprint before enabling APK installation. It requires one verified matching signer, exact application ID/version, and absence of `application-debuggable`, using [apksigner](https://developer.android.com/tools/apksigner) and SDK APK metadata inspection. A read-only Windows file handle with share-read locks the artifact against writing/replacement through signature inspection, same-handle hashing and native compilation; its bytes are capped at 200 MiB. The trusted digest is temporarily passed to the Rust build and the prior environment is restored. Actual Windows execution passed both the negative signer check and the positive packaging path.

The first signing-script review found that resetting directory inheritance while preserving existing explicit ACL entries could retain access for other users. The repaired script replaces directory ACLs and existing private-file ACLs with fresh owner/SYSTEM/Administrators entries; newly created private files inherit those entries. Windows verification of the actual directory, keystore and password file passed the allowed-SID check. The script uses .NET access-control methods with fresh ACL objects and trims the DPAPI record before decoding; the successful signing log verifies those runtime corrections. DPAPI protects the password for the current Windows user; it does not replace keystore access control. Signing material remains outside the repository. The signing certificate is exported as public DER and hashed separately to supply the desktop's expected signer; no private material is printed. The desktop build passes `--locked` through Tauri to Cargo, preserving the resolved checked-in dependency graph.

## Worldwide 0.2.0 boundary review

The user explicitly chose online primary plus optional offline maps. Fixed-provider native HTTPS and local-only production CSP replace the former no-runtime-network rule. Request bodies, paths, responses, rate limits and caches are bounded; redirects/proxies/cookies/provider headers are excluded. App activity is transient, but provider logging is disclosed and cannot be controlled by this application.

Independent ECC review found and corrected TileJSON decoding, SDK timers/diagnostics, archive/style/clear races, selected-file/protocol retention, decompression/directory bounds and offline path reconstruction/parity. Airport IDs are checked against the eligible static catalog before the 5 km tolerance; user endpoints retain 250 m. Actual flight QA found and fixed airport metadata leaking into strict native coordinate arguments, with exact-key regression coverage. Final release native integration passed 22 checks without JS exceptions/app console calls or direct remote webview requests. Native HTTPS still contacts the expected providers.

This remains a source/integration review, not an OS forensic audit or mobile hardware penetration test. Planet offline routing/standalone Android worldwide support and broad-distribution provider quotas are explicitly unfinished.

## 0.3 USB and responsive UI follow-up

Physical USB fallback requires present exact-serial Windows PnP evidence and an independent sole-USB ADB selector; a network socket or missing device path alone is insufficient. Literal localhost ADB daemon selection fixes cold start without opening a network listener. Public Hello precedes connection success and failures remove only the owned forward. Build-time APK source and staged handles block replacement, stage bytes are rehashed, and trusted resources are bundled without broad filesystem permissions.

Android Connect/Journey/Settings uses protected native inputs, RAM-only lifecycle state, explicit phone Start and revocation-first Stop. Preparation generation/revision/run ownership rejects late async responses and prevents older finalizers clearing new busy state. API 29 uses manager-level content-capture opt-out; API 30+ additionally uses guarded per-view exclusions. FLAG_SECURE and autofill/view saving restrictions remain.

Idle socket readiness is separated from the absolute five-second partial-frame deadline; preauthentication 120 s and authenticated lease 6 s remain. Observed expired/revoked credentials cannot fall back into preauthentication. Deterministic regressions and actual rendered measurements are recorded in [VALIDATION.md](VALIDATION.md), with [independent review](ANDROID_MOBILE_UI_REVIEW.md). Remaining sustained device/privacy boundaries are unchanged.
