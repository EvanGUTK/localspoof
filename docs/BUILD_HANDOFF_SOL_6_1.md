Airports now require open scheduled-service `large_airport` classification, for both automatic and manual selection. Current catalog has 1,153 eligible major airports among 3,269 entries. Jackson/MKL is rejected. Large-airport classification is a conservative major-hub policy, not verified international status or real flight availability.

Historical minor 4 required `liveJourneyControls:true` and `routeStops:true` plus prior capabilities. New authenticated revision-bound `SetSpeeds` accepts optional `walkMps` 0.1–3, `driveMps` 0.1–56 and `flightMps` 30–350. Initial flight speed is `flightSpeedMps`; legacy duration derives a bounded effective rate or rejects. Speeds change future movement from the current position without re-starting a plan. Snapshot supplies speeds, remaining time/distance, next-stop target and explicit wait state. Phone is authoritative; the map dot uses fresh DEVICE data before arming and actually submitted SIMULATION samples afterward. Pause/external waits do not promise an exact arrival.

`JumpToNextStop` is narrow and revision-bound, only available during applicable active travel with no pending placement/dwell. Ground jumps wait for successful provider submission before advancing distance/dwell; air/airport jumps retain placement and airplane/restoration barriers. Stop wins over stale actions. Exact retries retain a public acknowledgment and regenerate current authorized status without renewing the controller lease or repeating a mutation. Fixed pairing/heartbeat/frame limits and native-only credentials remain unchanged.

## Explicit local saves

Windows commands are `saved_load`, `saved_put`, `saved_delete`, `saved_clear`, `saved_import`; they accept a fixed validated portable schema rather than paths. Data lives under local application data in `saved-items-v1.json`. Only explicit mutation creates storage. Read-only startup does not write history. File bodies are capped at 512 KiB and 100 items; unknown fields, runtime authority, geometry/history and invalid points are rejected. Atomic write/rename and a native OS lock protect committed data and concurrent instances. Clear removes saved content; an empty coordination lock can remain.

Android uses an app-private AtomicFile excluded from backup. Explicit saved imports preserve original validated known fields, including boarding hold and USB policy; using a USB-policy template locally presents guided radio behavior rather than granting new capabilities. Explicit document picker import/export is available. Schema contains named/grouped PLACE or ROUTE templates, selected endpoints/stops/speeds/timing and flight options; no session token, pairing comparison, active radio state or automatic GPS history. Loading only edits a draft and never starts, reconnects or restores authority. Cross-platform plane-speed, per-stop dwell, boarding-hold and default-field round trips have regression coverage.
